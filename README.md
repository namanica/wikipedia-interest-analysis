# wikipedia-interest-analysis

Навичка у форматі [Agent Skills](https://agentskills.io/specification) для агента, який
допомагає засновникам B2C-продуктів оцінити інтерес аудиторії до теми в різних мовних
розділах Вікіпедії. На запит на кшталт «чи зростає інтерес до астрономії в українській
Вікіпедії» агент отримує готові метрики, рівень довіри, припущення й обмеження. На
прохання користувача також робить графік і PDF-звіт на одну сторінку.

## Що зроблено

- `SKILL.md` з інструкцією для агента і `references/` з довідкою по CLI, методологією
  та прикладами відповідей.
- Шість скриптів у `scripts/`. `run-analysis.js` закриває типовий запит однією
  командою, решта скриптів потрібні для окремих кроків, графіків і PDF.
- Код у `lib/` на Node.js 22 без збірки:
  - клієнт Pageviews API і Wikidata;
  - кеш на диску;
  - аналітика тренду й довіри;
  - графіки (Vega-Lite → SVG/PNG);
  - PDF (PDFKit).
- 71 тест на `node:test`: аналітика на синтетичних рядах, розбір відповідей API на
  заморожених фікстурах, інтеграційні тести всього ланцюжка без мережі.
- Сценарії перевірки на агентах: [evals/scenarios.md](evals/scenarios.md).

## Як це працює

```
запит користувача
  → агент (SKILL.md): визначає тему, мови, період
  → run-analysis.js
      1. тема → стаття в кожній мові (Wikidata: пошук + sitelinks)
      2. денні перегляди статей і всього розділу (Pageviews API, кеш, лише відсутні дні)
      3. аналітика: місяці → нормалізація → сплески → тренд → довіра → обмеження
      4. збереження запуску: ./wikipedia-interest-analysis-output/<run_id>/manifest.json
  → компактний JSON (≤ 4 КБ): summary, results, ranking, limitations, hints
  → агент формулює відповідь мовою користувача, не рахуючи нічого сам
  → на прохання: render-chart.js / build-report.js з того самого запуску
```

**Головна ідея: код відповідає за факти, модель — за мову.** Дешева модель погано
рахує статистику, але надійно переказує готові висновки. Тому всі відсотки, тренди,
рівні довіри й готові формулювання обмежень рахує код. Модель обирає команду і переказує
JSON. Кожне число у відповіді можна знайти у виводі.

**Архітектура:** `scripts/` → `lib/pipeline/` → домени (`api/wikimedia`, `cache`,
`analysis`, `charts`, `report`) → `models/` → `utils/`. Імпорти йдуть лише в один бік:
домени не знають один про одного, а збирає їх `pipeline`. Важкі бібліотеки для графіків
і PDF підвантажуються ліниво, тому текстовий запит виконується за ~0,1 с.

## Як навичка відповідає на вимоги завдання

| Вимога                                   | Як закрито                                                                                                                                                                                                                                                       |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Оцінка результатів і перевірка висновків | Сезонний тест Mann-Kendall і Sen's slope (сезонність не видається за тренд). Висновок перевіряється з і без сплесків, на сирих і нормалізованих даних, зі зсувом початку періоду. Рівень довіри `high/medium/low` виставляється за явними правилами з прапорцями |
| Висновки спираються на дані              | Модель не рахує, лише переказує JSON. Чеклист у `SKILL.md`: кожне число має бути у виводі                                                                                                                                                                        |
| Явні припущення й обмеження              | У кожному виводі є `assumptions` (період, нормалізація, сплески, тест, тип трафіку) і `limitations` (загальні + по одному реченню на кожен прапорець)                                                                                                            |
| Ефективні повторні й пов'язані запити    | Кеш денних точок із покриттям діапазонів: повтор дає `network_requests: 0`, «за 5 років» чи «додай мову» довантажує лише нове. Загальні перегляди розділу спільні для всіх тем. Назви статей кешуються окремо для кожної мови                                    |
| Уточнення і зміна припущень              | Усі припущення — параметри: `--years`, `--start`, `--raw`, `--keep-spikes`, `--min-monthly-views`, `--min-growth`, `--qid`. У `SKILL.md` є таблиця «що каже користувач → що змінити»                                                                             |
| Графіки і звіт для поширення             | `--chart` / `render-chart.js`: PNG і SVG. `build-report.js`: PDF рівно на одну сторінку (висновок, графік, таблиця, довіра, припущення, обмеження, що перевірити далі), підписи `en`/`uk`, кирилиця через вбудований Noto Sans                                   |
| Зручно для дешевої моделі                | Одна команда на типовий запит, компактний JSON, помилки з готовою наступною командою (`hint`), `SKILL.md` на 181 рядок, деталі в `references/`                                                                                                                   |
| Технічні вимоги                          | `SKILL.md` + власний код, що робить усю роботу з даними. Бінарників немає: PNG рендериться через WASM-версію resvg. Залежності фіксує `package-lock.json` і ставить `npm ci`, усе лежить у папці навички, папка лише читається                                   |
| Незалежність від агента                  | У `SKILL.md` немає інструментів чи змінних конкретного агента. Скрипти запускаються з робочої папки користувача, кеш лежить у системній папці кешу                                                                                                               |

## Встановлення і запуск

Потрібні Node.js 22+ та доступ до wikimedia.org і wikidata.org.

```sh
npm ci
ln -s "$PWD" ~/.claude/skills/wikipedia-interest-analysis   # приклад для Claude Code

node scripts/run-analysis.js --topic "astronomy" --langs uk
node scripts/run-analysis.js --topic "intermittent fasting" --langs pl,cs --years 2 --chart
node scripts/build-report.js --run latest --locale uk --summary "..."
```

Усі параметри описано в [references/cli.md](references/cli.md) або в `--help` кожного
скрипта. Кеш можна перенести змінною `WIKIPEDIA_INTEREST_CACHE_DIR`.

## Методологія коротко

Беремо денні перегляди від людей (`agent=user`) з усіх пристроїв і сумуємо їх у повні
календарні місяці. Далі:

1. **Нормалізація:** переводимо у перегляди на мільйон переглядів усього мовного розділу.
2. **Сплески:** дні понад 2× ковзної медіани за 29 днів (з модифікованим z-score)
   замінюємо медіаною.
3. **Тренд:** сезонний Mann-Kendall (p < 0,05) і Sen's slope у % на рік.
4. **Рік до року:** останні 12 місяців проти попередніх 12.
5. **Довіра:**
   - `low` — дуже мало переглядів, менше року даних або тренд тримається на сплесках;
   - `medium` — будь-який інший прапорець;
   - `high` — прапорців немає.

Повні правила й пороги — у [references/methodology.md](references/methodology.md).

**Обмеження підходу:**

- перегляди показують увагу до статті, а не попит чи готовність платити;
- враховано одну основну статтю теми;
- трафік усієї Вікіпедії у 2025–2026 роках падає (AI-відповіді в пошуку, фільтрація
  ботів), і нормалізація компенсує це лише частково, тож мови варто порівнювати між собою;
- перейменована стаття втрачає перегляди під старою назвою;
- у PDF не підтримуються CJK, арабська й іврит.

## Перевірка якості

- **Автоматичні тести** (`npm test`, 71 тест, < 1 с, без мережі):
  - статистика на синтетичних рядах з відомою відповіддю: тренд крізь сезонність, чиста
    сезонність без тренду, сплески, нормалізація проти росту всього розділу, рік до року,
    індекс, рівень довіри й прапорці для кожного сценарію;
  - розбір реальних відповідей API з `test/fixtures/wikimedia/`, 404 як «даних немає»;
  - повтори на 5xx і 429 з `Retry-After`;
  - логіка діапазонів і свіжості кешу;
  - інтеграційні тести всього ланцюжка на фейковій Wikimedia: `network_requests: 0` при
    повторі, довантаження лише різниці, запобіжник, PNG і PDF рівно на одну сторінку.
- **Звірка з першоджерелом.** Місячні суми з денних даних збіглися з місячним
  ендпоінтом Pageviews API для «Астрономія» (uk) за всі 35 місяців. Сирий показник рік до
  року (−59,6%) збігся з ручним розрахунком за API, тобто з тим, що показує
  pageviews.wmcloud.org.
- **Ручні прогони на реальних даних** після кожного етапу: астрономія (uk), інтервальне
  голодування (pl, cs, uk, en), англійська як іноземна (5–9 мов), DeepSeek (нова стаття
  зі сплеском), неіснуючі статті, теми й мови. Графіки й PDF переглянуто візуально.
- **Що знайшли й виправили завдяки перевіркам:**
  - `--years 2` після вирівнювання давав 23 місяці й прибирав рік до року;
  - вивід для 5+ мов перевищував бюджет;
  - легенда графіка обрізалася;
  - таблиця PDF переносила довгі назви;
  - тест виявив прихований тренд у синтетичному шумі фікстури.
- **Використання AI.** Код писався з Claude Code поетапно за планом:
  1. агент пропонував план етапу;
  2. я погоджувала або сперечалася;
  3. агент реалізовував етап і проганяв `npm run lint`, ручні запуски й тести;
  4. я рев'юїла етап і приймала коміти.

  Після затвердження стилю й архітектури останні етапи агент виконав самостійно за тим
  самим циклом, а результат я перевіряю рев'ю і прогонами на агентах.

  Результати AI перевірялися звіркою з API, візуальним переглядом графіків і PDF, тестами
  з відомою відповіддю та прогонами на дешевій моделі
  ([evals/scenarios.md](evals/scenarios.md)).

## План розвитку

1. **Тематичні кластери.** Тема — набір статей: основна плюс пов'язані через Wikidata
   (підкласи, «частина від») з агрегованим інтересом. Формат теми вже підтримує кілька
   статей.
2. **Більші обсяги.** SQLite (`node:sqlite`) замість JSON-файлів за тим самим інтерфейсом
   `get / set / missingRanges`. Bulk-дампи pageviews замість API для десятків мов і років.
   Попередня агрегація місяців.
3. **Точніша аналітика:**
   - декомпозиція сезонності (STL);
   - поправка на загальне падіння трафіку Вікіпедії через кошик контрольних статей;
   - розбивка за пристроями (мобільний перекіс);
   - облік перейменувань через історію редиректів.
4. **Пакетні порівняння** десятків мов і тем з ранжуванням, збереженими профілями критеріїв
   і звітом на кілька сторінок.
5. **Крос-перевірка** з іншими джерелами (пошукові тренди, опитування) як окремий домен,
   коли з'явиться друге реальне джерело.

## Залежності

| Пакет                      | Навіщо                                                  |
| -------------------------- | ------------------------------------------------------- |
| `vega`, `vega-lite`        | декларативний опис графіків і рендер у SVG без браузера |
| `@resvg/resvg-wasm`        | SVG → PNG без нативних бінарників                       |
| `pdfkit`, `svg-to-pdfkit`  | PDF з вбудованим шрифтом і векторним графіком           |
| `eslint`, `prettier` (dev) | стиль і перевірка циклів імпорту                        |

Ядро (API, кеш, аналітика) працює лише на вбудованих модулях Node. Шрифт Noto Sans
поширюється за ліцензією OFL: [assets/fonts/OFL.txt](assets/fonts/OFL.txt).
